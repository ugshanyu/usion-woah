# Lessons

- Treat a managed service subscription or payment method as an explicit product decision. Surface the account and billing gate before integrating that provider, and keep provider adapters replaceable behind the authenticated ICE endpoint.
- Treat NAT traversal reliability as a product tradeoff, not an implicit infrastructure mandate. This product explicitly chose STUN-only direct P2P and accepts that some restrictive networks cannot start a match; preserve that choice unless the owner asks to revisit TURN.
- Do not treat HTTP health, asset availability, CSP, or Permissions-Policy headers as proof that a camera game works. Before publishing, exercise the real embedded Start gesture through MediaPipe initialization and `getUserMedia`; match a module Worker with MediaPipe's module WASM loader, avoid blocking the camera prompt on full detector prewarm, and surface typed startup errors instead of collapsing vision and camera failures into one message.
- Keep camera inference limited to the mechanic that truly needs vision. When pointing becomes an explicit touch gesture, remove pose models, pose calibration, and pose classifiers rather than leaving an unused detector in the startup path.
- Never give an iframe app's `index.html` a positive freshness lifetime when releases must appear immediately. Serve HTML with `no-store` and cache only content-hashed JS/CSS assets as immutable; otherwise the Usion WebView can keep rendering a previous deployment after Railway is Online.
- A guided vision calibration must advance on recognition evidence, not elapsed time or generic face visibility. Require consecutive stable samples that match the prompted movement, expose searching/move-more/hold feedback, and never discard valid calibration samples merely because inference is slow.
- When the product changes an interaction primitive, remove the obsolete implementation and naming end to end. A four-button choice must not remain modeled, tested, documented, or reported as a swipe; turn ownership and timeout penalties must be explicit host-authoritative state.
- A transport's initial `disconnected` value is not evidence of a dropped match. Enter reconnect UI only after that transport has reached `connected`, and leave it deterministically after recovery.
- `GAME_ROOM_ASSIGNED` already makes the Usion SDK connect and join. The game should adopt the assigned room and wait for `onJoined`; calling `connect()`/`join()` again creates a competing solo-to-multiplayer transition.
- Platform-room recovery and WebRTC ICE recovery are separate state machines. Pause active round timing for either, but never leave the UI in an indefinite shared “reconnecting” phase after ICE becomes connected again.
- Do not apply synchronized-gesture timing rules to a precommitted guess. A direction button is chosen once during the countdown and locks immediately; only the defender's camera movement is measured on the WOAH beat, and the guess deadline closes at that beat.
- A temporal gesture rule must be derived from the detector's worst supported cadence. Never require consecutive samples closer together than the adaptive inference interval, and never apply a second confidence threshold that silently makes the classifier's documented entry threshold meaningless.
- Do not make players demonstrate every runtime direction when the detector can expose canonical player-centric yaw/pitch. Use one short, stable forward-facing baseline and keep the four-direction evidence requirement inside the tested classifier instead of onboarding.
- Never derive synthetic head-pose tests from the implementation's assumed matrix convention. Pin the exact MediaPipe Web matrix serialization and camera-axis signs from the bundled runtime/official source, test matrices generated in that convention, and cross-check direction signs against image landmarks before shipping player-centric labels.
- A camera verdict must be evidence-driven, not timer-driven. Open recognition on the visible/audio beat, publish as soon as stable capture-timestamped evidence exists, and use the maximum window only as a true timeout; never finalize at an arbitrary short delay before a slower device can produce the required frames.
- Do not let a low-fidelity landmark proxy veto the primary 3D head-pose estimator, and do not reuse a narrow session-global neutral threshold as per-round face-presence evidence. Rearm each candidate direction from recent valid face frames while rejecting only a genuinely held copy of that candidate.
